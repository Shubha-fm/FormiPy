# SoftwareX Phase 3: controlled property-aware comparison

This experiment compares two finite safety-property families with paired reference and deliberately mutated UML inputs. It runs actual TLC for each model and separately executes **purpose-built** pytest assertions against exported Python code. This is not the default generated pytest suite.

- State machine: the chosen safety condition forbids hazard while in Cruise; the mutant redirects a hazard transition from Stop to Cruise. The Python test exercises the same named transition and checks the prototype's Cruise safety predicate. The scope is deliberately limited because the general generated Python semantics are not equivalent to the formal state-machine model.
- Use case: a forbidden actor/use-case association is injected. The test directly checks whether the exported Python allowed-pairs relation contains that forbidden association.

Ten numbered repeats per family yield 20 references and 20 mutants. The numbered variants are **template repeats**, not 40 independently designed real-world models. The results must be interpreted as controlled defect-detection checks, not broadly generalizable sensitivity estimates.

The study records per-case model input, raw TLC output, pytest output, CSV verdicts, and run metadata. If an expected outcome is not observed, the workflow fails and preserves partial evidence. It does not modify the production UI, its default pytest generator, or the published application.

To reproduce in the repository with Python 3.12, Java 17 and the TLC JAR installed:

```bash
python -m pip install -r backend/requirements-dev.txt
python backend/install_tlc.py
PYTHONPATH=backend python scripts/run_softwarex_phase3_2026.py
```

Do not combine the Phase 3 mutation rates with Phase 2's default smoke-suite results, because they use different test oracles. A larger, independently sampled and property-matched corpus is required before quantitative claims about relative detection power.
